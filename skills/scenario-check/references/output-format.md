# Output Format

検査結果の報告の形。問題の内容は `uiai check --json` の `code`・`level`・`message`・`where` をそのまま使う（言い換えない）。

## 基本構造

```markdown
## シナリオ検査結果

### {ファイル}

| ID | レベル | 場所 | 内容 |
|----|--------|------|------|
| {code} | エラー / 警告 | {where} | {message} |

---

### まとめ

| ファイル | エラー | 警告 | 状態 |
|----------|--------|------|------|
| login.yaml | 0 | 1 | WARN |
| search.yaml | 2 | 0 | FAIL |

**合計: エラー 2, 警告 1**
```

- 問題のないファイルは、まとめの表にだけ載せる。
- `場所` は `steps[1]（ログイン） actions[2]` の形（0 から数えたセクションとアクションの番号。括弧内はセクションの `id`）。重複キーなどは行番号になる。

| 状態 | 条件 |
|------|------|
| PASS | エラーも警告もない |
| WARN | 警告だけ |
| FAIL | エラーがある |

## 修正案つき（fix=true dry-run=true）

表に「自動修正」列（可 / -）を足し、可のものは変更前後を示す。

````markdown
### login.yaml

| ID | レベル | 場所 | 内容 | 自動修正 |
|----|--------|------|------|----------|
| E011 | エラー | steps[2]（ログイン） | `id` 「ログイン」が重複している | 可 |
| W007 | 警告 | config.verify | `config.verify` は廃止（AI の画像判定に一本化）。無視する | 可 |
| W002 | 警告 | steps[0]（起動） | セクションに `then` がない | - |

#### E011: steps[2]

```yaml
# Before
  - id: "ログイン"
# After
  - id: "ログイン_2"
```
````

## 修正後（fix=true）

表の「自動修正」列を「修正済」にし、修正したことの一覧と、修正後に `uiai check` をもう一度実行した結果を添える。

```markdown
### 修正内容

- E011: steps[2] の `ログイン` を `ログイン_2` に変更
- W007: `config.verify` を削除

### 修正後の検査

エラー 0, 警告 1（W002: 自動修正できない）
```

## 終了コード（`uiai check`）

| コード | 条件 |
|--------|------|
| 0 | エラーなし（`--strict` なら警告もなし） |
| 1 | エラーあり、または `--strict` で警告あり |
| 2 | シナリオが見つからない |
