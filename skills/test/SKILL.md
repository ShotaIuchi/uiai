# /uiai:test

シナリオ（YAML）を `uiai run` で実行する。エンジンがループを回し、AI は 1 ステップにつき 1 回、画面を見て判断する。
シナリオの書き方は [references/scenario-schema.md](references/scenario-schema.md)。

`uiai` はこのプラグインの `bin/` にあり、プラグインが有効な間は PATH から呼べる。前提は uv だけ（Python と依存は自動で用意される）。

## 引数

`$ARGUMENTS` をそのまま `uiai run` に渡す。シナリオが指定されていなければ、作業フォルダの `*.yaml` からシナリオらしいもの（`name`・`app`・`steps` を持つもの）を探して、どれを実行するかユーザーに確認する。

| オプション | 意味 |
|---|---|
| `--platform android\|ios\|web\|all` | 実行するプラットフォーム。省略時は `app` と接続中の対象から決まる（セクションの `on` に書いたプラットフォームは候補から外す）。`on` のあるセクションは、`on` のデバイスで実行する |
| `--model <名前>` | AI のモデル（既定 haiku） |
| `--rejudge-model <名前>` | `then` の不合格を確定する前に判定し直すモデル（既定 sonnet。`none` で無効） |
| `--type-delay <ミリ秒>` | 文字入力の 1 文字ごとの間隔（シナリオの `config.type_delay` より優先。既定 0 = 最速）。Android の日本語など ASCII 以外は一度に貼り付ける |
| `--var NAME=VALUE` | 変数の値（繰り返し可） |
| `--serial <シリアル>` | Android 端末（複数接続しているとき。`--parallel` では繰り返して複数指定できる） |
| `--udid <UDID>` | iOS シミュレータか、USB でつないだ iPhone（複数あるとき。`--parallel` では繰り返して複数指定できる） |
| `--ios-team <チーム ID>` | iPhone で使う WebDriverAgent の署名チーム（Xcode にサインインしたチームが複数あるとき） |
| `--parallel` | 端末ごとに並列で実行する（Android は接続中の全端末、iOS は USB でつないだ全 iPhone と起動中の全シミュレータ、Web は `--browsers` 個のブラウザ。既定 2）。シナリオは空いた端末に割り当てる（`on` のあるシナリオは、並列の分が終わったあとに 1 件ずつ） |
| `--headed` | Web のブラウザを表示する |
| `--fail-on-warning` | 警告付き合格も失敗として扱う |
| `--webhook <URL>` | 失敗を Slack などにも送る（環境変数 `UIAI_WEBHOOK_URL` でも可） |

## 手順

### 1. 実行できるか確かめる

```sh
uiai run <シナリオ>... [オプション] --dry-run
```

実行はせず、シナリオごとに「どのプラットフォームで実行するか」と「値のない変数」を表示する。`✗` の行があれば、内容に応じて対処してからもう一度確かめる。

| 表示 | 対処 |
|---|---|
| `uiai: command not found` | プラグインが有効か確認する。uv がなければ入れ方を案内する（https://docs.astral.sh/uv/） |
| シナリオの形式エラー | エラーを伝え、`/uiai:scenario-check` で直せることを案内して止まる。勝手に直さない |
| 複数のプラットフォームが候補 | どれで実行するか（`all` も可）をユーザーに聞き、`--platform` を付ける |
| 実行対象が見つからない | Android は端末・エミュレータの接続（`adb devices`）、iOS はシミュレータの起動（Simulator.app か `xcrun simctl boot <UDID>`）か、iPhone を USB でつなぐことを案内する |
| 値のない変数（秘密でない） | ユーザーに値を聞き、`--var NAME=VALUE` で渡す |
| 値のない変数（秘密） | **チャットで値を聞かない**（会話に残るため）。表示された環境変数を設定してから Claude Code を起動し直すか、ユーザー自身が端末で `uiai run` を実行すれば対話入力できることを伝える |

### 2. バックグラウンドで実行する

run id を決める。日時は推測せず `date +%Y%m%d-%H%M%S` で取り、`test-<日時>` とする。Bash の `run_in_background` で起動する。

```sh
uiai run <シナリオ>... [オプション] --run-id <run id>
```

1 ステップ 3〜6 秒、10 ステップのシナリオで 30〜60 秒が目安。初回は依存の取得に 1 分ほどかかる。シナリオが多く、端末が複数あるか Web のときは、`--parallel` を付けると速くなることを提案してよい（付けるかはユーザーに聞く）。

### 3. 失敗を見張る

起動したらすぐ、Monitor ツールで見張る（`timeout_ms` は 600000）。

```sh
uiai watch --run <run id> --wait 300 --timeout 540
```

Monitor には寿命の上限がある（環境によっては 10 分）。`watch` はそれより少し早く自分で終わり、続きを見るためのコマンドを出す。

`watch` は、失敗（`then` の不合格・`do` の失敗・実行エラー）が起きるたびに 1 行出し、実行が終わると終了する。

- 失敗の行が届いたら、その都度チャットで短く知らせる（どのシナリオの、どのステップが、なぜ）。修正や再実行は勝手に始めない。
- ユーザーが席を離れていそうなら（長い実行の途中など）、PushNotification も送る（使えるときだけ）。
- 「watch の時間切れ」の行が出たら、実行がまだ終わっていなければ、その行に書かれたコマンド（`--skip` 付き。`--wait 300 --timeout 540` も付ける）で Monitor を張り直す。
- 時間切れの行がないまま Monitor が切れたら、`--skip` なしで張り直す。それまでの失敗がもう一度出るが、知らせ直さない。
- 実行エラーの行が届いたら、下の「実行できなかったとき」を見る。

### 4. 結果をまとめる

バックグラウンドの `uiai run` が終わったら、`.uiai/results/<run id>/summary.md` を読み、次をまとめて返す。

- シナリオごとの結果（合格・警告付き合格・不合格・未実行）と所要時間
- 不合格のステップ: 期待結果、AI の理由、読み取った文字（strict のとき）
- 警告（想定外のダイアログを閉じた、何もしなかった、判定が分かれた（haiku は不合格、再判定の sonnet は合格）、など）と、未実行のステップ
- スキップしたステップ（`optional: true` の `do` が失敗した）とその理由
- 詳しく見るためのレポート: `.uiai/results/<run id>/<シナリオ>-<プラットフォーム>/report.html`（画像とタップ位置つき）

不合格の原因がアプリ側かシナリオ側か分からないときは、`result.json` の `calls`（呼び出しごとの操作・理由・判定）と `call_NN.jpg` を見て推測を添える。推測であることは明記する。シナリオの修正は、ユーザーに確認してから行う。

作業フォルダの `.gitignore` に `.uiai/` がなければ、追加を提案する（結果フォルダは大きくなる）。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | すべて合格（警告付き合格を含む） |
| 1 | 不合格か未実行のステップがある |
| 2 | 最後まで実行できなかった |

## 実行できなかったとき（終了コード 2）

| 症状 | 対処 |
|---|---|
| run id の結果フォルダが既にある | 別の run id で起動し直す |
| Chromium がない | `uiai setup` を実行してブラウザを取得し（ユーザーに伝えてから）、もう一度実行する |
| `claude` がない、認証エラー | Claude Code CLI のインストールとログインを案内する |
| 端末が見つからない・途中で切れた | `adb devices` の確認を案内する |
| AXe が見つからない（iOS） | `brew install cameroncooke/axe/axe` で入れられることを伝える。入れるのはユーザーに確認してから |
| 起動中の iOS シミュレータが複数ある、iPhone とシミュレータの両方がある | 表示された中からどれを使うかユーザーに聞き、`--udid` を付ける |
| iOS シミュレータで日本語を入力する `do` が失敗した | iOS シミュレータは ASCII 以外の文字の入力に未対応であることを伝える |
| WebDriverAgent をビルド・起動できない（iPhone） | エラーに出た対処（Xcode へのサインイン、デベロッパモード、UI オートメーション、開発元の信頼、ロックの解除）を伝える。iPhone 側の操作はユーザーにしてもらう。署名チームが複数あるときは、どれを使うか聞いて `--ios-team` を付ける |
| 「WebDriverAgent をビルドする」と出て時間がかかっている | 初回のビルドは数分かかることを伝えて待つ |

## 注意

- スクリーンショットは Anthropic の API に送られる。秘密の値（`secret: true`）は AI に渡さず、記録からも伏せるが、画面に平文で表示された内容は送られる。
- 実行中の端末・シミュレータ・ブラウザは操作しないよう、ユーザーに伝える。
- Android で文字を入力するシナリオは、端末のクリップボードの中身を上書きする。
- CI で使う方法は、このプラグインの `docs/ci/README.md`。
